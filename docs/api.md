# API and code-first OpenAPI

Gin provides routing through Huma’s official `humagin` adapter. Go HTTP DTOs and `huma.Register` operation declarations are the source of truth. Huma derives
OpenAPI 3.1 schemas and allocates/validates a fresh input for each request. Business entities
remain independent of JSON/schema tags. Do not maintain a parallel TypeScript contract.

```sh
make openapi
make contract-check
```

`api/openapi.json` is generated; do not edit manually. The generator uses the same registration
path as the running service, without opening a socket, database or SaaS connection. CI compares
generated output with the committed artifact. Local/test serve `/openapi.json`, `/openapi.yaml`
and `/docs`; production/staging disable documentation routes by default. The docs UI loads
its renderer from a public CDN; the raw spec remains available offline through generation.

Each operation declares a stable operation ID, summary, description, tags, typed body/query/path
fields, success status, known error responses and authentication schemes. Permission requirements
are stated in descriptions; scopes are enforced by application use cases.

| Operation | Permission | Success |
|---|---|---|
| POST /api/v1/users | users:write | 201 |
| GET /api/v1/users/{id} | users:read | 200 |
| GET /api/v1/users?limit=20&offset=0 | users:read | 200 |
| GET /livez | public | 200 |
| GET /readyz | public | 200 or 503 |

Lists use data/limit/offset, stable creation-time/ID ordering and a maximum limit of 100.
Offset is bounded at 100000. For growing datasets, introduce cursor pagination as an explicit
contract change. Missing resources return 404, uniqueness conflicts 409, invalid payloads 422,
oversized bodies 413, insufficient permissions 403, missing/invalid credentials 401, and disabled
listing 503. Application deadline failures return 504. Errors from typed routes use Huma's
RFC 9457 problem JSON with generic unexpected-error details. Router-level unknown routes/methods
use net/http 404/405 responses through Gin fallbacks; unsupported methods include an Allow header.
Baseline GET routes also accept HEAD, and trailing-slash mismatches are not silently redirected. X-Request-ID is generated by the server for every request.

The HTTP suite verifies validation, concurrency, request isolation, security/error behavior and
representative responses. Review generated schema changes as API changes; a generated spec
alone does not prove compatibility with existing clients.
